# Public service differential

Start the pinned official v1.13.10 reference and Rust on separate loopback addresses, then run:

```sh
REFERENCE_URL=http://127.0.0.1:8480 LIVEKIT_URL=http://127.0.0.1:8580 node functional-services.mjs
```

The coordinator owns both servers and cleanup. The reference is a test peer, never a Rust product runtime dependency. Default test keys are the official public development credentials; configure `LIVEKIT_API_KEY` and `LIVEKIT_API_SECRET` when appropriate. Tokens are generated by the unmodified installed official server SDK and never retained in results.

`service-contracts.json` enumerates all47 registered OSS methods from the five pinned protocol schemas and records source hashes. Each is exercised with six HTTP input cases: malformed JSON, scalar, array, null, malformed protobuf and a valid empty unauthenticated request. Results compare HTTP status, content type and the complete decoded error envelope. AgentDispatch additionally checks real default creation, explicit create/list/filter/delete, missing deletion and room deletion/recreation. Only nondeterministic resource IDs, the fixture's distinct room names and positive nanosecond timestamps are mapped in dispatch observations.

This is not proof of executing all47 API methods. Recording/transcoding, ingress publication, SIP calls, worker assignment, Redis and full RoomService effects remain independent requirements. Decode/permission/negative-input success cannot close those parent capabilities. The first actual HTTP run found TransferSIPParticipant's presence-before-auth difference; its failure evidence is preserved.

Every failure exits nonzero. Output is `output/functional-services.json`; archive sanitized results with actual binary/source identity before cleanup. No existing SDK/media/congestion assertion is changed by this optional profile.
