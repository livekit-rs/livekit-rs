## Cleanup and limits

Each case closes its real socket, then actual ServerSDK.DeleteRoom and polls ListRooms until owned name absent. A genuine cleanup-only not_found is accepted only followed by real empty ListRooms (e.g. original idle-room cleanup); other API errors fail. Actual socket must remain OPEN/error-free before intentional close; closure event bounded, code retained. Cleanup is separate from config acceptance; no assertion of all close-code behavior or internal server leak freedom. All owned cleanup attempts occur on failure (including an ambiguous failed create request) and cleanup errors fail the run. Generated room/participant names are retained only in resource_ownership cleanup receipts, without tokens or credentials, so the coordinator can remove any interrupted owned resources. Runner creates only RESULT mode0600/create-new; it spawns no server/browser, creates no cert/temp config. Root persists reproducible evidence, then removes task-owned runtime outputs/config/logs and stops only its servers. Fixture source inputs/pins are reproducible inputs, not disposable output.

Resume is explicitly OPEN. Reconnect query alone is not genuine resume: original transport/session state and SID/grant history must exist. This fixture does not pretend signal-only raw Join is a completed ICE/DTLS/SDK session, send fake SDP, or label new Join as resume. Actual main Join config scope is the batch gate; native browser codec use/media and true Join→RTC→signal loss→Resume config remain separate.
