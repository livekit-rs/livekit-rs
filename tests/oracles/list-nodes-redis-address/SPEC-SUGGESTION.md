# Candidate spec: list-nodes Redis address/transport consumption

Status: source-designed, NOT_RUN. Follow-on to SPEC0048; preserve original stored-node16, exact raw CLI16, displaywidth/scalar, selected credentials and BasicAuth acceptance.

Fixed cmd/server/commands.go listNodes loads config, constructs NewLocalNode and InitializeRouter. Protocol redis.GetRedisClient passes a simple-mode Address unchanged into go-redis UniversalOptions. Its actual Options.init selects UNIX for an address beginning `/`, otherwise TCP. TCP uses Go SplitHostPort then LookupPort; this is not a URL grammar. Credentials and DB are separate fields, not userinfo/path/query percent-decoding. On successful setup the real client PINGs, then RedisRouter.ListNodes issues HVALS nodes. The command must not register, delete or update any node.

Port domain includes explicit empty/zero, signed decimal forms, service names, bracketed IPv6 and zone identifiers. Missing port, bracket placement, extra colons and invalid numeric port failures have source-defined net.OpError/AddrError stages. Actual OS dial failures must come from the attempted socket and typed cause; no input-based fake refusal or fabricated successful connection is allowed. UNIX path punctuation is literal, including percent/hash/at/colon/question mark. TCP wildcard/empty host must not be rejected merely because a URI library disallows it.

The existing Rust driver can receive ConnectionAddr directly. Proposed production is confined to list-nodes: source-shaped address projection into Tcp/Unix, separate unchanged credentials, database projection matching Go SELECT(db) only when db>0, and actual typed UNIX IO error formatting. Do not alter shared Redis worker configuration or normalize table text. Database negatives are an additional source-defined boundary: Go leaves DB0, while the Rust driver otherwise sends SELECT for any db!=0.

Named services use the already-declared libc service database boundary on UNIX, matching original CGO LookupPort, plus its fixed native fallback. This adds no crate. Exact arbitrary DNS failure text, resolver policy switches/build-tag selection, address-race/family selection and exceptional NSS/OS failures are separate OPEN domains until independently source-observed. Do not advertise this candidate as complete arbitrary-net.Dial equivalence merely because the finite address matrix passes. IPv6 zones are retained literally into the real driver resolver; require a source/runtime control on a host with a usable scoped address before claiming that leaf.

Independent original Go observer and real main matrix must retain the original10 address/ENV cases and add negativeDB without replacing them. All comparisons use functional outcome, exact streams/exit and actual node selection; elapsed time is not an assertion. Tests-only baseline must use pre-existing lk_config parse/list_nodes APIs and compile before its actual behavior failures count as RED. The same unchanged tests/cases then run against candidate. No new helper or type may be required by the baseline tests.

Source-chain correction: static credential resolution (Options.resolveCredentials) alone is insufficient to infer authentication. Actual Hello and fallback AUTH append credentials only when password is nonempty (commands.go360-374, redis.go811). Username-only/empty-password is therefore not a confirmed Rust difference and receives no production change.
