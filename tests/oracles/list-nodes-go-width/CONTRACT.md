## Call chain and scope

Fixed commands.go -> tablewriter prepareContent -> twwidth.Width -> calculateRunewidth -> displaywidth.Options{EastAsianWidth: actualGlobal}.Rune. Blueprint.formatCell also calls twwidth.Width. This is per-rune source behavior, so 👩ZWJ👩 and a regional indicator pair each measure 4; combining e+mark measures 1. String-grapheme width is not an interchangeable implementation.

The scalar port implements original Options.Rune for every valid Unicode scalar, both EastAsianWidth modes. The real twwidth composite literal leaves ControlSequences and ControlSequences8Bit false. There is no SoftHyphen option in this selected source: soft hyphen width comes from the exact trie. It must not be inferred from a similarly named option in a different crate/version.

Source twwidth.Width has an additional one-byte ASCII fast path returning 1 (including single NUL/DEL), except TAB which calls source TabWidth. Its multi-byte/string path sums original Rune widths after ANSI strip. WidthWithOptions does not have that fast path. The port keeps these two entry points separate. It also implements the source measurement-only CSI/OSC regex behavior and accepts explicit tab/border/EAW policy parameters. None of the measured/stripped string is used as output text.

The proposed narrow list-nodes integration invokes the actual Width entry with a controlled narrow/default policy: EastAsianWidth=false, ForceNarrowBorders=false, tab_width=8. This is sufficient for the existing plain source9/renderer12 and official16 domains, and retains original text. It is NOT a port of host policy discovery. Source EastAsianDetect uses RUNEWIDTH_EASTASIAN overrides, terminal/WSL/Windows/VTE/Alacritty probes and normalized locale; source TabWidth consults TABWIDTH/TS/VIM_TABSTOP/editorconfig and heuristics. They remain separate OPEN host-adapter work. Do not claim all ENV/tab/ANSI/Unicode terminal behavior is accepted from the scalar port, even if its isolated explicit-policy tests pass. Full ANSI measurement vectors are authored but NOT_RUN; tab defaults and source init/cache behavior need actual counterpart receipts. No changes to visual LF splitting, whole-cell trimming, render output bytes, or wire decoding are included.
